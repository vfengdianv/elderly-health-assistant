## 1. 项目概述

### 1.1 项目背景
随着我国人口老龄化程度不断加深，老年人健康管理成为社会关注的重点。传统的健康管理方式存在记录困难、信息分散、缺乏个性化指导等问题。本系统旨在通过信息化手段，为老年人提供智能化、一体化的健康管理服务。

### 1.2 项目目标
- 提供便捷的用药提醒和药物信息查询服务
- 实现科学的饮食营养管理和规划
- 提供个性化的运动指导和健康追踪
- 集成AI智能助手，提供24小时健康咨询服务
- 构建用户友好的交互界面，降低老年人使用门槛

### 1.3 目标用户
- **主要用户**：50岁及以上的老年人群
- **次要用户**：老年人的家属和护理人员

### 1.4 系统特色
1. **智能化**：集成DeepSeek AI大模型，提供智能健康咨询
2. **个性化**：根据用户健康档案提供定制化建议
3. **便捷性**：简洁友好的界面设计，适合老年人操作
4. **全面性**：覆盖用药、饮食、运动等多个健康维度

## 2. 需求分析

### 2.1 功能性需求

#### 2.1.1 用户认证模块
- **用户注册**：支持邮箱注册，密码加密存储
- **用户登录**：JWT Token认证机制
- **个人资料管理**：支持用户信息修改、健康档案维护

#### 2.1.2 AI智能助手模块
- **智能对话**：基于DeepSeek AI的自然语言交互
- **健康咨询**：提供用药、饮食、运动等方面的专业建议
- **对话历史**：保存用户对话记录，支持历史查询

#### 2.1.3 用药管理模块
- **用药提醒**：创建、编辑、删除用药计划
- **药物信息查询**：查询药物详细信息、用法用量

#### 2.1.4 饮食管理模块
- **饮食计划**：制定每日三餐及加餐的营养计划
- **营养追踪**：记录每日热量、蛋白质、脂肪、碳水化合物摄入
- **营养统计**：可视化展示营养摄入趋势

#### 2.1.5 运动指导模块
- **运动计划**：制定个性化运动计划
- **运动追踪**：记录运动时长、类型、消耗热量
- **数据分析**：趋势图表展示运动数据

### 2.2 非功能性需求

#### 2.2.1 性能需求
- **响应时间**：普通请求响应时间 < 500ms
- **AI响应**：AI对话响应时间 < 3秒
- **并发支持**：支持至少100个并发用户

#### 2.2.2 可用性需求
- **系统可用性**：≥ 99%
- **数据备份**：每日自动备份
- **错误恢复**：异常情况下能够优雅降级

#### 2.2.3 安全性需求
- **数据加密**：密码使用bcrypt加密存储
- **传输加密**：支持HTTPS协议
- **权限控制**：基于JWT的用户身份认证
- **数据隔离**：用户数据严格隔离，互不可见

#### 2.2.4 易用性需求
- **界面友好**：采用Ant Design组件库，界面简洁美观
- **中文化**：所有界面元素完全中文化
- **操作简便**：减少操作步骤，降低学习成本

## 3. 系统架构设计

### 3.1 总体架构

本系统采用**前后端分离**的B/S架构，前端采用React框架，后端采用Node.js + Express框架。

```
┌─────────────────────────────────────────────────────────┐
│                      用户层 (Browser)                    │
│                    React SPA Application                │
└──────────────────────┬──────────────────────────────────┘
                       │ HTTP/HTTPS
                       │ RESTful API
┌──────────────────────▼──────────────────────────────────┐
│                   应用层 (Application)                   │
│              Node.js + Express Server                   │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐              │
│  │  Auth    │  │ Business │  │   AI     │              │
│  │ Service  │  │  Logic   │  │ Service  │              │
│  └──────────┘  └──────────┘  └──────────┘              │
└──────────────────────┬──────────────────────────────────┘
                       │
         ┌─────────────┼─────────────┐
         │                           │
┌────────▼──────────┐      ┌─────────▼──────────┐
│   数据层 (Data)    │      │  外部服务 (External)│
│   MongoDB         │      │   DeepSeek API     │
│   Database        │      │                    │
└───────────────────┘      └────────────────────┘
```

### 3.2 技术架构层次

#### 3.2.1 前端架构
```
前端层次架构：
├── 表现层 (Presentation Layer)
│   ├── React Components (功能组件)
│   ├── Ant Design UI (界面组件)
│   └── CSS Styling (样式)
├── 状态管理层 (State Management)
│   ├── React Context (全局状态)
│   └── Local State (组件状态)
├── 业务逻辑层 (Business Logic)
│   ├── API Request (请求封装)
│   ├── Data Processing (数据处理)
│   └── Form Validation (表单验证)
└── 路由层 (Routing)
    └── React Router (路由管理)
```

#### 3.2.2 后端架构
```
后端层次架构：
├── 路由层 (Routes)
│   ├── API Routing (路由定义)
│   └── Middleware (中间件)
├── 控制层 (Controllers)
│   ├── Request Handling (请求处理)
│   └── Response Formatting (响应格式化)
├── 业务逻辑层 (Services)
│   ├── Business Rules (业务规则)
│   ├── AI Integration (AI集成)
│   └── Data Validation (数据验证)
└── 数据访问层 (Data Access)
    ├── Mongoose Models (数据模型)
    └── Database Operations (数据库操作)
```

### 3.3 核心设计模式

#### 3.3.1 前端设计模式
- **组件化设计**：功能模块组件化，提高复用性
- **容器/展示组件分离**：业务逻辑与UI展示分离
- **高阶组件 (HOC)**：权限校验、路由保护
- **Context模式**：全局状态管理（用户认证状态）

#### 3.3.2 后端设计模式
- **MVC模式**：模型-视图-控制器分离
- **中间件模式**：请求拦截、认证、日志记录
- **工厂模式**：统一的响应格式化
- **单例模式**：数据库连接管理

## 4. 数据库设计

### 4.1 数据库选型
**MongoDB** - NoSQL文档型数据库

**选型理由**：
1. 灵活的Schema设计，适合快速迭代
2. 良好的JSON数据支持，与Node.js无缝集成
3. 高性能的读写能力
4. 支持丰富的查询操作

### 4.2 数据模型设计

#### 4.2.1 用户模型 (User)
```javascript
{
  _id: ObjectId,              // 用户ID
  username: String,           // 用户名 (唯一)
  email: String,              // 邮箱 (唯一)
  password: String,           // 加密密码
  createdAt: Date,           // 创建时间
  updatedAt: Date            // 更新时间
}
```

#### 4.2.2 健康档案模型 (HealthProfile)
```javascript
{
  _id: ObjectId,
  userId: ObjectId,          // 关联用户
  age: Number,               // 年龄
  gender: String,            // 性别
  height: Number,            // 身高 (cm)
  weight: Number,            // 体重 (kg)
  bloodType: String,         // 血型
  allergies: [String],       // 过敏史
  chronicDiseases: [String], // 慢性病史
  emergencyContact: {        // 紧急联系人
    name: String,
    phone: String,
    relationship: String
  },
  createdAt: Date,
  updatedAt: Date
}
```

#### 4.2.3 用药提醒模型 (Medication)
```javascript
{
  _id: ObjectId,
  userId: ObjectId,          // 关联用户
  medicationName: String,    // 药物名称
  dosage: String,           // 剂量
  frequency: String,        // 频次
  startTime: Date,          // 开始日期
  endTime: Date,            // 结束日期
  instructions: String,     // 备注说明
  createdAt: Date,
  updatedAt: Date
}
```

#### 4.2.4 饮食计划模型 (DietPlan)
```javascript
{
  _id: ObjectId,
  userId: ObjectId,
  planDate: Date,           // 计划日期
  breakfast: {              // 早餐
    description: String,
    calories: Number,
    protein: Number,
    fat: Number,
    carbs: Number
  },
  lunch: { ... },           // 午餐 (同上)
  dinner: { ... },          // 晚餐 (同上)
  snacks: { ... },          // 加餐 (同上)
  caloriesTarget: Number,   // 热量目标
  notes: String,            // 备注
  createdAt: Date,
  updatedAt: Date
}
```

#### 4.2.5 运动计划模型 (ExercisePlan)
```javascript
{
  _id: ObjectId,
  userId: ObjectId,
  planDate: Date,           // 计划日期
  activityType: String,     // 活动类型 (散步/跑步/游泳等)
  duration: Number,         // 时长 (分钟)
  distance: Number,         // 距离 (公里)
  intensity: String,        // 强度 (低/中/高)
  caloriesBurned: Number,   // 消耗热量
  completed: Boolean,       // 是否完成
  notes: String,            // 备注
  createdAt: Date,
  updatedAt: Date
}
```

#### 4.2.6 AI对话记录模型 (Conversation)
```javascript
{
  _id: ObjectId,
  userId: ObjectId,
  messages: [               // 对话消息数组
    {
      role: String,         // 角色 (user/assistant)
      content: String,      // 消息内容
      timestamp: Date       // 时间戳
    }
  ],
  createdAt: Date,
  updatedAt: Date
}
```

## 5. 功能模块设计

### 5.1 用户认证模块

#### 5.1.1 注册流程
```
用户输入信息 → 前端验证 → 发送注册请求 
→ 后端验证 → 密码加密 → 存储数据库 
→ 返回成功/失败 → 跳转登录页
```

#### 5.1.2 登录流程
```
用户输入凭证 → 前端验证 → 发送登录请求 
→ 后端验证密码 → 生成JWT Token 
→ 返回Token → 前端存储 → 跳转首页
```

#### 5.1.3 权限验证
- 使用JWT中间件验证所有受保护的API
- Token过期时间：24小时
- 前端路由保护：ProtectedRoute组件

### 5.2 AI智能助手模块

#### 5.2.1 对话流程
```
用户输入问题 → 前端发送请求 → 后端接收
→ 调用DeepSeek API → 获取AI回复 
→ 保存对话记录 → 返回前端 → 展示回复
```

#### 5.2.2 上下文管理
- 保存最近10轮对话作为上下文
- 系统提示词：专注于老年人健康领域
- 异常处理：API失败时返回友好提示

### 5.3 用药管理模块

#### 5.3.1 用药提醒功能
- **创建提醒**：设置药物名称、剂量、频次、时间范围
- **编辑提醒**：修改现有提醒信息
- **删除提醒**：支持二次确认删除
- **列表展示**：表格形式展示所有提醒

#### 5.3.2 药物信息查询
- 输入药物名称进行查询
- 调用DeepSeek API获取药物信息
- 展示用法用量、注意事项等

### 5.4 饮食管理模块

#### 5.4.1 饮食计划功能
- **创建计划**：为指定日期创建三餐及加餐计划
- **营养录入**：记录热量、蛋白质、脂肪、碳水化合物
- **计划查看**：表格展示历史计划
- **数据修改**：支持编辑和删除

#### 5.4.2 营养统计功能
- 统计总热量、平均营养素摄入
- 饼图展示营养素比例
- 支持日期范围筛选

### 5.5 运动指导模块

#### 5.5.1 运动计划功能
- **创建计划**：设置运动类型、时长、强度等
- **完成标记**：标记计划完成状态
- **热量计算**：根据强度自动计算消耗热量

#### 5.5.2 运动追踪功能
- **趋势图表**：7日运动时长和热量趋势
- **活动统计**：不同运动类型的热量消耗饼图
- **完成率统计**：显示计划完成率

## 6. 接口设计

#### 6.1.1 RESTful风格
- **GET**：查询资源
- **POST**：创建资源
- **PUT**：更新资源
- **DELETE**：删除资源

#### 6.1.2 统一响应格式
```javascript
// 成功响应
{
  "success": true,
  "message": "操作成功",
  "data": { ... }
}

// 失败响应
{
  "success": false,
  "message": "错误信息",
  "error_code": "ERROR_CODE"
}
```

## 8. 安全性设计

### 8.1 认证与授权

#### 8.1.1 密码安全
- 使用bcrypt加密，加盐轮次：10
- 密码最小长度：6位
- 不在日志中记录明文密码

#### 8.1.2 JWT安全
- Token有效期：24小时
- Secret密钥存储在环境变量
- 每次请求验证Token有效性

### 8.2 数据安全

#### 8.2.1 数据隔离
- 所有业务数据通过userId严格隔离
- 用户只能访问自己的数据
- 后端强制校验数据归属

#### 8.2.2 输入验证
- 前端表单验证
- 后端参数验证
- 防止SQL注入（NoSQL注入）
- XSS防护

### 8.3 传输安全

- 生产环境使用HTTPS
- 敏感数据加密传输
- CORS配置限制跨域访问

### 8.4 API安全

- 请求频率限制
- 异常请求监控
- 错误信息脱敏
