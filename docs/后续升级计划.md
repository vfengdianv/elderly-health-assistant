## 0. 结论摘要（先读这一段）

**一句话结论：代码实现已明显超出 v1.0 文档范围，但存在"文档声称已完成、实际未实现或未验证"的系统性偏差；当前最紧要的不是加功能，而是先修安全硬伤与三个"假功能"。**

三条判断：

1. **安全层面存在可直接被利用的高危缺陷。** 真实 DeepSeek API Key 明文存在 4 处（`.env` 2 处 + 源码 3 处，其中 1 处重合），JWT 密钥缺失时回退到硬编码字符串（等于可伪造任意用户身份），3 个 AI 接口完全没有鉴权（可被盗刷额度）。
2. **产品核心价值尚未闭环。** 产品叫"健康智能助手"，主打"准时提醒，安全用药"，但**系统中不存在任何提醒投递机制**——没有定时任务、没有推送、没有短信/邮件；`Medication` 只是数据库里的一条记录，"提醒"从未真正发生过。
3. **文档可信度需要重建。** `HealthProfile`（健康档案，文档 §4.2.2 的核心模型）是一个字段齐备但方法全是 `TODO` 的纯 class，**不是 Mongoose 模型，全仓无任何引用**；`MedicationAdvice` 组件在 3 份文档中标 ✅ 但文件不存在；`TESTING_GUIDE.md` 的测试记录表**全部未勾选**，而 `ACCEPTANCE_CHECKLIST.md` 却声称"全部测试通过"。

**最紧急的 5 件事（本周内，预计 3 人日）**

| # | 动作 | 原因 |
|---|------|------|
| 1 | 轮换 DeepSeek API Key，从源码与 `.env` 中移除，改由环境变量注入 | Key 已随 `server.rar`、源码副本外泄，**轮换前任何代码修改都无意义** |
| 2 | 启动时强制校验 `JWT_SECRET`，缺失即拒绝启动 | 当前回退密钥公开可见，可伪造任意账号 Token |
| 3 | 给 `/api/ai/chat`、`/speech-to-text`、`/pose-analysis` 补 `auth` 中间件（或直接下线） | 无鉴权接口会被人白嫖 API 额度 |
| 4 | 修复 3 处 React Hooks 违规（提前 return 在 hooks 之前） | 登录态变化时整页白屏，是用户可感知的崩溃 |
| 5 | 修正 `Auth.css` 的 `:global()` 写法 | 普通 CSS 中 `:global()` 非法，11 条规则被浏览器整体丢弃，登录页样式失效 |

  4. 新增 `.gitignore`，纳入 `.env`、`node_modules`、`build/`、`*.rar`。

### P0-2 认证与授权加固（2 人日）🔴

- **动作**
  1. 启动时强校验：`JWT_SECRET` 未配置或等于默认值时，打印错误并 `process.exit(1)`（`auth.js:3`、`authController.js:5` 去掉 `||` 回退）。
  2. 把 `JWT_SECRET`、`JWT_EXPIRE` 补进 `server/.env` 与 `deploy/生产环境.env`，并在 `ecosystem.config.js` 显式设置 `cwd` 与 `env_file`（消除 CWD 依赖导致的密钥回退）。
  3. `aiRoutes.js:13-15` 三个接口补 `auth`；若 `/chat` 已废弃则直接删除。
  4. JWT 有效期从 7d 收敛到 **2h + refresh token**；加 `tokenVersion` 字段，登出与改密时自增，中间件比对版本号实现真正吊销。
  5. 中间件查库校验 `isActive`，停用账号立即失效。
  6. 移除 `req.query.token` 支持，只认 `Authorization` 头。
- **验收**：① 未设 `JWT_SECRET` 时服务拒绝启动；② 用默认密钥签发的 Token 调用接口返回 401；③ 登出后原 Token 立即 401；④ 停用账号的存量 Token 立即 401。

## 4. P1｜核心价值闭环（第 3–8 周，约 25–30 人日）

### P1-1 用药提醒投递引擎（10 人日）⭐ 最高业务价值

**这是把产品从"Excel 替代品"变成"助手"的关键一步。**

- **需求**：到点真实触达用户；用户可一键确认服药；未确认时升级通知家属。
- **设计要点**
  1. **调度层**：`node-cron` + MongoDB 扫描（单机足够），或 `agenda`（自带持久化与重试）。时间存 UTC，展示按 `Asia/Shanghai`；`Medication.reminderTimes[]` 已存在，可直接复用。
  2. **投递层（按适老性排序）**：① **微信服务号模板消息**（老年人最普及、无需装 App、系统通知可达性最高，强烈推荐作为主力）；② 短信（兜底，成本可控地只用于未确认升级）；③ 邮件（家属）；④ 浏览器 Web Push（桌面端补充）。
  3. **确认闭环**：推送内带"已服用/稍后提醒/跳过"；未确认 30 分钟 → 重推；仍未确认 → 通知紧急联系人。
  4. **数据**：新增 `MedicationRecord {userId, medicationId, plannedTime, actualTime, status, source}`，支撑依从性统计。
  5. **可靠性与合规**：幂等（同一 `plannedTime` 不重复投递，唯一索引兜底）；失败重试与死信记录；开关 `isActive` 尊重用户暂停。
- **验收**：创建一条 2 分钟后到点的提醒 → 真实收到推送 → 点击确认后数据库出现 `status=taken` 记录 → 不点击时 30 分钟后家属收到升级通知 → 依从性统计页可看到本周服药率。
- **风险**：微信服务号需认证主体（个人主体受限）→ **请在 P1 启动前先确认可用通道**，否则退回"短信 + 邮件 + Web Push"组合。

### P1-2 适老化改造（10 人日）⭐ 产品立命之本

- **动作**
  1. **全局主题**：用 antd `ConfigProvider theme` token 统一提升——正文 ≥16px（推荐 18px）、行高 ≥1.8、主按钮 ≥48px、次要文字色 ≥ `#595959`（对比度 ≥4.5:1，修复当前 `#999` 约 2.8:1 的问题）。
  2. **"大字模式"开关**：`localStorage` 持久化 + CSS 变量驱动，支持基础/大/特大三档；全站去 px 硬编码，改 `rem`。
  3. **语音双通道**：语音输入（复用已存在的 `/speech-to-text`，前端用 Web Speech API 接入）+ 结果朗读（`speechSynthesis`）。这是老年人最真实的刚需。
  4. **无障碍**：所有图标按钮加 `aria-label`；首页 `<div onClick>` 卡片改为 `<button>` 或加 `role/tabIndex/onKeyDown`；清理 9 处 `<a href="#">` 伪链接；弹窗焦点管理。
  5. **降低表单复杂度**：饮食计划弹窗单个表单要一次填 **23 个输入项**（4 餐 × 5 项营养字段，由 `DietPlan.js:217-238` 的 `mealForm` helper 渲染、`:337-346` 调用；加日期、热量目标、备注）→ 拆为分步向导（日期 → 三餐 → 目标）；术语口语化（"蛋白质(g)/碳水(g)"加示例与默认值）。
  6. **错误提示适老化**：去掉英文 `error.message` 拼接，改为"网络不太好，请稍后重试"级别的中文 + 重试按钮。
- **验收**：① 特大档下全站无截断/重叠；② 键盘 Tab 可完成登录 → 记饮食 → 看统计全流程；③ 语音说出"我今天的血压"能被识别并提交；④ axe/Lighthouse 无障碍评分显著提升（目标 ≥90）。
